# Evaluation Module

Evaluates the coverage plan produced for each zone and aggregates the results
into a district-level report. Evaluation consumes the segmented cells, coverage
paths, sequence paths, map masks, and planning-stage timings generated by the
pipeline.

## Components

- **ZoneEvaluationHandler** (`zone_evaluation_handler.py`): Runs the configured zone evaluator and exposes the resulting statistics.
- **ZoneEvaluationBase** (`zone_evaluation_base.py`): Base interface for zone evaluators and shared validation/persistence logic.
- **ZoneEvaluation** (`zone_evaluation_mh.py`): Current concrete evaluator for timing, path, travel, and cleaning metrics.
- **ZoneStatsBase** (`zone_evaluation_base.py`): Data object containing the serialized KPIs for one zone.
- **DistrictEvaluationHandler** (`district_evaluation.py`): Aggregates completed zone statistics.
- **DistrictStatsBase** (`district_evaluation.py`): Data object containing the serialized district KPIs.

## Evaluation Flow

```text
SegmentationMetrics + SequencePaths + timing checkpoints
       |
       v
  ZoneEvaluationHandler
       |
       v
      ZoneStatsBase
       |
       v
    zone result.json

ZoneStatsBase objects for all zones
       |
       v
       DistrictEvaluationHandler
       |
       v
   DistrictStatsBase
       |
       v
  district result.json
```

## Zone Evaluation

`ZoneEvaluationHandler.evaluate()` requires:

- `paths`: a `SequencePaths` instance containing coverage paths in pixels and metres, connection paths, and the final full path;
- `segmentation_metrics`: the `SegmentationMetrics` produced after segmentation and cell merging;
- `times`: a dictionary containing `start`, `segmentation`, `coverage_planning`, and `sequencing` timestamps.

The evaluator validates the timing data and requires a non-empty full path and
coverage paths. It then saves the populated `ZoneStatsBase` to the zone's
configured `result.json` file. `get_stats()` returns the same statistics object
for district aggregation.

## Zone Metrics

### Counts and timing

| Field                     | Meaning                                           | Units   |
| ------------------------- | ------------------------------------------------- | ------- |
| `n_cells`                 | Total segmented cells                             | count   |
| `n_cov_cells`             | Cells that have coverage paths                    | count   |
| `ptime_segmentation`      | Segmentation elapsed time                         | seconds |
| `ptime_coverage_planning` | Coverage-planning elapsed time                    | seconds |
| `ptime_sequencing`        | Sequencing elapsed time                           | seconds |
| `ptime_pipeline`          | Total time from pipeline start through sequencing | seconds |

### Segmentation metrics

These values are copied from `SegmentationMetrics` and are arithmetic averages
over the zone's processed cells:

| Field                    | Meaning                                              | Units         |
| ------------------------ | ---------------------------------------------------- | ------------- |
| `seg_avg_area`           | Average cell area                                    | square pixels |
| `seg_avg_perimeter`      | Average cell perimeter                               | pixels        |
| `seg_avg_free_perimeter` | Average free boundary sampled from the workspace map | pixels        |
| `seg_avg_compactness_a`  | Average `area / perimeter**2`                        | dimensionless |
| `seg_avg_compactness_b`  | Average `area / rotated_bounding_box_area`           | dimensionless |

### Path and travel metrics

| Field                  | Meaning                                            | Units   |
| ---------------------- | -------------------------------------------------- | ------- |
| `path_full_length`     | Length of the complete path, including connections | metres  |
| `path_coverage_length` | Total length of coverage paths only                | metres  |
| `path_yaw_full`        | Sum of heading changes on the complete path        | radians |
| `path_yaw_coverage`    | Sum of heading changes on coverage paths           | radians |
| `trav_time_full`       | Estimated full-path travel time                    | seconds |
| `trav_time_coverage`   | Estimated coverage-only travel time                | seconds |

Travel time is estimated from linear and angular motion limits:

```text
travel_time = path_length / v_lin_avg + yaw_change / v_ang_avg
```

The limits come from `RobotConfig.v_lin_avg` and `RobotConfig.v_ang_avg`.

### Cleaning and coverage metrics

| Field              | Meaning                                             | Units         |
| ------------------ | --------------------------------------------------- | ------------- |
| `cleaning_area_px` | Number of cleanable pixels in the zone              | pixels        |
| `area_cleaning_m`  | Cleanable area                                      | square metres |
| `cleaned_area_px`  | Cleanable pixels reached by buffered coverage paths | pixels        |
| `area_cleaned_m`   | Area reached by coverage paths                      | square metres |
| `area_uncleaned_m` | Cleanable area not reached                          | square metres |
| `area_overlaped_m` | Estimated swept area beyond the unique cleaned area | square metres |
| `area_coverage_pc` | Cleaned area divided by cleanable area              | percent       |
| `area_overlap_pc`  | Estimated overlapped area divided by cleanable area | percent       |

Cleaned pixels are accumulated by buffering each coverage path with the
configured cleaning radius and masking the result to free, cleanable space.
The physical cleaned area is calculated as:

```text
area_cleaned_m = cleaned_area_px * resolution**2
```

The estimated swept area uses coverage path length and cleaning width:

```text
total_swept_area_m = path_coverage_length * (2 * cleaning_r)
area_overlaped_m = total_swept_area_m - area_cleaned_m
```

## District Aggregation

`DistrictEvaluationHandler.evaluate(zone_stats)` accepts one `ZoneStatsBase`
per completed zone. It:

- sums cell counts, travel times, processing times, path lengths, yaw changes, and areas;
- averages the segmentation metrics across zones;
- recomputes district coverage and overlap percentages from aggregated areas;
- writes the resulting `DistrictStatsBase` to the configured district result file.

District path fields use `l_path_full` and `l_path_coverage` to distinguish
them from the corresponding zone fields `path_full_length` and `path_coverage_length`.

## Result Files

Zone results are stored under the zone's method directory:

```text
maps/<map_name>/District/Zone_<i>/<method>/result.json
```

The district result is stored at the district-level result path configured by
the caller. All JSON values are rounded for reporting; lengths and areas are
reported in the units described above.
